# Deploying Latte (all free tiers)

| Piece | Service | Free tier (Aug 2026) |
|-------|---------|----------------------|
| Database | **Neon** Postgres | 0.5 GB storage, 100 CU-hrs/mo, scales to zero after 5 min idle. No card, never expires, commercial use OK. |
| Backend API | **Render** web service | 512 MB / 0.1 CPU, 750 hrs/mo, spins down after 15 min idle (~1 min cold start). |
| Frontend | **Vercel** Hobby | 100 GB transfer/mo. Personal / non-commercial use only. |

> Both Render and Neon sleep when idle, so the first request after a quiet spell
> can take ~1 minute. Fine for a hobby app.

---

## Step 1 — Neon database

1. Sign up at [neon.tech](https://neon.tech) (GitHub login, no card).
2. **Create project** — name `latte`, region closest to your Render region
   (e.g. AWS `us-east-1` / Oregon). Postgres 16 default is fine.
3. On the project dashboard, **Connection string** → choose the **Pooled
   connection** and copy it. It looks like:
   ```
   postgresql://latte_owner:XXXX@ep-xxx-pooler.us-east-1.aws.neon.tech/latte?sslmode=require
   ```
   Use the **pooled** host (`...-pooler...`) — the API opens a connection per
   request and the pooler handles that cleanly.
4. Keep this string for Step 2. No schema setup needed — the API creates its
   tables on first boot.

---

## Step 2 — Render backend (Blueprint)

1. Push `main` (this repo already has `render.yaml`).
2. [dashboard.render.com](https://dashboard.render.com) → **New → Blueprint** →
   connect `github.com/ArmouredOre/Latte`.
3. Render reads `render.yaml` and proposes one web service **`latte-api`** (free).
   Approve.
4. It prompts for the `sync: false` env vars — set:

   | Key | Value |
   |-----|-------|
   | `DATABASE_URL` | the Neon **pooled** connection string from Step 1 |
   | `GOOGLE_CLIENT_ID` | `437995674022-1mgeulk90gh7dp5d1hkpo9h5qut99i6j.apps.googleusercontent.com` |
   | `CORS_ORIGINS` | `https://latte-plum.vercel.app,http://localhost:5173` |

   `JWT_SECRET` is generated by Render automatically.
5. Deploy. Build = `pip install -r requirements.txt`, start = `uvicorn ...`.
   Watch the log; on boot it connects to Neon and runs `create_all`.
6. Grab the service URL (e.g. `https://latte-api.onrender.com`) and test:
   ```
   curl https://latte-api.onrender.com/api/health   ->  {"status":"ok"}
   ```
   (first hit may take ~1 min while it spins up).

---

## Step 3 — Vercel frontend

1. Vercel project (`latte-plum`) → **Settings → Environment Variables**
   (Production + Preview):

   | Key | Value |
   |-----|-------|
   | `VITE_API_URL` | the Render service URL, e.g. `https://latte-api.onrender.com` (no trailing slash) |
   | `VITE_GOOGLE_CLIENT_ID` | `437995674022-1mgeulk90gh7dp5d1hkpo9h5qut99i6j.apps.googleusercontent.com` |

2. **Redeploy** the frontend (Deployments → ⋯ → Redeploy) — Vite bakes env
   vars in at build time, so a plain push isn't enough if you only changed
   env vars.
3. Base path is already handled: `vite.config.js` uses `base: '/'` by default
   (Vercel) and `/Latte/` only when `npm run deploy` sets `GH_PAGES=1`.

---

## Step 4 — Google OAuth origins

Google Cloud Console → APIs & Services → Credentials → your OAuth client →
**Authorized JavaScript origins** — must include every origin the sign-in button
loads on:

- `http://localhost:5173`
- `https://<your-app>.vercel.app`
- any custom domain

The Render API URL does **not** go here.

---

## Step 5 — verify end to end

1. Open the Vercel site, sign in with Google.
2. Create a list, add a row — it should auto-save.
3. Refresh — data persists (now in Neon).
4. Neon dashboard → **Tables** → you should see `users` and `sheets` populated.

---

## Notes / hardening still open

- `/docs`, `/redoc`, `/openapi.json` are public. Hide with
  `FastAPI(docs_url=None, redoc_url=None, openapi_url=None)` for production.
- No rate limiting yet.
- 7-day JWT, no server-side revocation.
- If you ever move off Neon: `DATABASE_URL` accepts `postgres://` /
  `postgresql://` and is auto-upgraded to the psycopg driver.
